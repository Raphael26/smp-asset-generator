# Project notes

- Local-only studio for Spanish Mum in Paris social visuals. README.md has the map of files.
- Runs on port 4747 only (`npm run dev`, `npm start`, `Studio.command`). Next allows one dev server per project.
- UI in English; the content of the visuals is French by default, or English per asset: `CreateOptions.language` (home page) becomes `content.options.language` (switchable in `PostInspector`), read everywhere through `languageOf()`. The renderers use `typo()` (French or English typography) and the `DRAWN` / `universeLabel` labels from `tokens.ts`, every Claude request ends with `languageRule()` from `voice.ts`, and `lint.ts` checks the rules of that language. The main flow is prompt → visual (`src/lib/ai/compose.ts`, `/api/create`); changes from the editor's prompt bar are proposals she applies.
- Generated photos are tied to slides via `slide.photoJob` / `job.request.targetSlideId`; the editor polls and `placePhoto` fills the slide server-side too.
- Never let an image model draw text: photos come from Replicate, all text is set by `SlideView` in the brand fonts.
- Social photo slides: `photo` crops (object-fit cover, focal point and zoom in `ImageRef`); `photo-full` shows the photo whole. `fullPhotoZone(format, ratio)` in `layouts.ts` gives the zone and the photo box from the photo's width ÷ height (full-bleed when wide enough, otherwise inset within the margins); `SlideView` measures the ratio from the loaded `<img>` and holds `data-ready` (the `pending` argument of `useFit`) until then, so exports never capture the default proportions. The inspector's *Framing* chips switch between the two templates.
- Next.js 16 with `cacheComponents: false`: pages are client components that call the `/api` route handlers.
- Paths built from `process.cwd()` in server code carry `/* turbopackIgnore: true */`; without it the dev server watches `data/` and reloads the page on every database write.
- A4 documents are formats with `shape: "a4"` (794 × 1123 px) and `doc-*` page templates rendered by `DocPage.tsx`; `layoutsFor(format)` / `equivalentLayout` keep social and document templates apart. Each A4 format has a landscape twin `<id>-landscape` (1123 × 794, `landscapeOf`) built in `formats.ts`: `getFormat` knows both, pickers list the portrait ones plus `OrientationChoice`, and `docs.css` lays them out under `data-orientation="landscape"`. Moodboard photos live in `slide.gallery` (jobs target `targetGallery`).
- Presentations are formats with `shape: "slide"` (1920 × 1080, ids `deck-*`, `isDeck`). `DocPage.tsx` renders them like a landscape page: `docs.css` zooms the inner frame 2× (a 960 × 540 page), so the document sizes become slide sizes. `deck-section` and `deck-agenda` are `kind: "deck"` templates; `layoutsFor` gives decks the document pages too. Speaker notes are `slide.notes` (never drawn; Claude writes them through `SlideOut.notes`). The `pptx` export captures each slide as a PNG and assembles the file with pptxgenjs (listed in `serverExternalPackages`).
- Free slides (layout `free`, `manual: true` so Claude never composes it) hold `slide.blocks` (text / image / box / line / table, `src/lib/brand/blocks.ts`) in the 960 × 540 design units, painted in order by `DocPage.tsx`; `slide.chrome` picks the logo/footer. The editor overlays `FreeCanvas.tsx` on the stage (drag, resize, snap, type in place) and `BlockInspector.tsx` in the panel; `unlock.ts` turns a rendered template slide into blocks by measuring the `data-free` attributes `DocPage` puts on every text, photo, box and table. `compose.ts` returns free slides untouched when Claude edits a deck.
- Typing on template slides: every field-bound text in `DocPage.tsx` and `SlideView.tsx` carries `data-field`; `InPlaceText.tsx` (overlaid by `Stage.tsx` on non-free slides) opens a textarea over the clicked element with its computed type (lengths scaled by drawn width ÷ computed width, which is exact under both `zoom` and `transform`) and writes the field back. Previews pass `links={false}` so document pages draw spans, not anchors, inside the library's links.
- Never use the browser's `confirm()` / `alert()`: embedded browsers block them silently (deletions looked broken). Use `ConfirmDialog` (`src/components/ui/`) or make the action undoable. The editor records an undo step on every content change in `update()` (bursts under 500 ms share one step); Undo, Redo and Save sit in the header.
- Preview and export share `src/components/slides/SlideView.tsx`; exports go through `/render/[id]` in headless Chrome (`src/lib/render/export.ts`).
- Schema change: edit `src/lib/db/schema.ts`, run `npm run db:generate`, commit the migration in `drizzle/`.
